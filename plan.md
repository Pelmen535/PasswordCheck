Рабочий документ. Обновляется по мере выполнения: выполненный пункт отмечается `[x]`.
План может меняться по мере продвижения.

## Технические решения

Зафиксированы на старте. Изменение любого пункта — отдельное обсуждение в команде, а не самостоятельное решение одного участника.

| Область | Решение |
|---|---|
| Язык и версия | Java 21 |
| Сборка | Maven |
| HTTP-клиент | `java.net.http.HttpClient` (встроенный) |
| JSON | Jackson |
| Хранилище | SQLite через JDBC — файловое, без отдельного сервера |
| Логирование | SLF4J + Logback |
| Тесты | JUnit 5, AssertJ, WireMock для подмены HIBP |
| Конкурентность | Виртуальные потоки, блокирующие сигнатуры |
| Стиль коммитов | Conventional Commits |

Принцип, определяющий архитектуру: **ни один секрет не сохраняется** — ни в базе, ни в логах, ни на диске. Любая подзадача, нарушающая это, отклоняется.

## Зависимости этапов

```
0 → 1 → 2, 3, 4
        4 → 5 → 6
        3 + 6 → 7

        7 + 9 → 10 → 11
```

Этапы 2, 3 и 4 после завершения первого независимы и могут выполняться параллельно двумя участниками.

## Разделение работы

Крупные этапы разбиты так, чтобы подзадачи внутри них были независимы: матчеры этапа 5 и парсеры этапа 7 распределяются между участниками поштучно. Оба участника работают в одних и тех же модулях, что делает взаимное ревью содержательным.

По каждому этапу вклад фиксируется в pull request'ах: у каждого участника свои ветки и свои коммиты в рамках одного этапа.
