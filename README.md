# PasswordCheck

Telegram-бот для парольной гигиены: генерирует стойкие пароли и парольные фразы, оценивает реальное время взлома существующих, проверяет их по базе утечек по протоколу k-anonymity и следит за появлением сервисов пользователя в новых утечках — при этом не сохраняя ни одного пароля.

Семестровый проект по разработке чат-ботов, УрФУ.

## Зачем

Типичная проблема не в том, что человек не знает про надёжные пароли, а в том, что проверить свои он не может: любая онлайн-проверялка требует ввести пароль на чужом сайте, а менеджеры паролей показывают проблемы только внутри себя.

PasswordCheck закрывает четыре задачи:

**Генерация.** Парольные фразы по методу Diceware и пароли под ограничения конкретного сайта — вроде «максимум 16 символов, обязательна цифра, запрещены кавычки».

**Оценка стойкости.** Не наивная энтропия, по которой `P@ssw0rd123` выглядит надёжным, а разбор по образцам: словарные слова, транслит, клавиатурные последовательности для QWERTY и ЙЦУКЕН, даты, повторы, замены букв цифрами. Результат — не абстрактное «средний», а время взлома при разных моделях атакующего.

**Проверка по базе утечек.** Пароль сверяется с базой Have I Been Pwned, не покидая устройства.

**Мониторинг сервисов.** Пользователь перечисляет, где у него есть аккаунты — это не секретная информация. Бот сопоставляет список с каталогом известных утечек и предупреждает, если сервис в нём появился.

## Чего бот не делает

Эти ограничения заложены в архитектуру намеренно:

- **не хранит пароли** — ни в открытом виде, ни в виде хешей, ни в виде отпечатков;
- **не является менеджером паролей** и не пытается заменить Bitwarden или KeePass;
- **не пишет секреты в логи** — это проверяется отдельным тестом.

## Как проверка не раскрывает пароль

Используется протокол k-anonymity сервиса Have I Been Pwned. Локально считается SHA-1 пароля, на сервер уходят только первые пять символов хеша, в ответ приходит около тысячи суффиксов с этим префиксом, и сопоставление происходит уже локально. Сервер не знает, какой пароль проверялся, и не может его восстановить.

## Ограничения

Сообщение, отправленное в Telegram, попадает на серверы Telegram. Бот удаляет входящее сообщение с секретом сразу после обработки, но это убирает его из переписки, а не из инфраструктуры мессенджера. Поэтому основной сценарий — генерация, где секрет создаётся ботом и никуда не пересылается, а проверка присланного пароля сопровождается явным предупреждением.
