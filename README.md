# PasswordCheck

Telegram-бот для парольной гигиены: генерирует стойкие пароли и парольные фразы, оценивает реальное время взлома существующих, проверяет их по базе утечек по протоколу k-anonymity и следит за появлением сервисов пользователя в новых утечках — при этом не сохраняя ни одного пароля.

Семестровый проект по разработке чат-ботов, УрФУ.

## Что делает

**Генерация.** Парольные фразы по методу Diceware и пароли под ограничения конкретного сайта («максимум 16 символов, обязательна цифра, запрещены кавычки»). Источник случайности — `SecureRandom`, распределение равномерное.

**Оценка стойкости.** Не наивная энтропия `log₂(алфавит^длина)`, по которой `P@ssw0rd123` выглядит надёжным, а разбор по образцам: словарные слова, транслит, клавиатурные последовательности для QWERTY и ЙЦУКЕН, даты, повторы, l33t-подстановки. Результат переводится во время взлома при разных моделях атакующего — от онлайн-перебора с троттлингом до фермы GPU по быстрому хешу.

**Проверка по базе утечек.** Пароль сверяется с базой Have I Been Pwned, не покидая устройства (см. ниже).

**Аудит выгрузки.** Разбор CSV-экспорта из Bitwarden, KeePass, Chrome или Яндекс.Браузера: проверка каждой записи по базе утечек, оценка стойкости, поиск переиспользованных паролей. На выходе — список того, что менять в первую очередь. Файл обрабатывается в памяти и не сохраняется.

**Мониторинг сервисов.** Пользователь перечисляет, где у него есть аккаунты — это не секретная информация. Бот сопоставляет список с каталогом известных утечек и предупреждает о совпадениях, в том числе о новых, появившихся позже.

## Чего бот не делает

Эти ограничения заложены в архитектуру намеренно и не будут сняты:

- **Не хранит пароли** — ни в открытом виде, ни в виде хешей, ни в виде отпечатков.
- **Не является менеджером паролей.** Он не заменяет Bitwarden или KeePass и не пытается ими стать.
- **Не сохраняет загруженные файлы.** Выгрузка разбирается в памяти и уничтожается сразу после формирования отчёта.
- **Не пишет секреты в логи.** Это проверяется отдельным функциональным тестом.

Соответственно, поиск переиспользованных паролей работает только внутри одной загруженной выгрузки. Сравнение между разными сеансами потребовало бы хранить отпечатки паролей, а это противоречит основному принципу.

## Как работает проверка по базе утечек

Используется протокол k-anonymity сервиса [Have I Been Pwned](https://haveibeenpwned.com/API/v3):

1. Локально считается SHA-1 пароля.
2. На сервер отправляются **только первые 5 символов** хеша.
3. В ответ приходят 800–1000 суффиксов хешей с этим префиксом и счётчиками появления в утечках.
4. Сопоставление происходит локально.

Сервер не знает, какой именно пароль проверялся, и не может его восстановить. Запросы отправляются с заголовком `Add-Padding: true`, чтобы по размеру ответа нельзя было судить о результате проверки.

API бесплатен и не требует ключа.

## Модель угроз и ограничения

Честная оговорка, которую стоит понимать до использования.

Сообщение, отправленное в Telegram, попадает на серверы Telegram. Бот удаляет входящее сообщение с секретом сразу после обработки, но это убирает его из переписки, а не из инфраструктуры мессенджера. Поэтому:

- основные сценарии — **генерация** (секрет создаётся ботом и никуда не пересылается) и **аудит файла** (файл удаляется немедленно);
- проверка отдельного пароля через `/check` сопровождается явным предупреждением и предназначена для разовых проверок, а не для ежедневного использования.

Внутри процесса секреты хранятся в `char[]` и обнуляются после обработки. JVM не гарантирует отсутствие копий в памяти — это известное ограничение платформы, а не недосмотр.

## Команды

| Команда | Назначение | Статус |
|---|---|---|
| `/help [команда]` | справка по всем командам или по одной | ✅ |
| `/about` | назначение бота | ✅ |
| `/author` | информация об авторах | ✅ |
| `/gen` | генерация пароля под заданные ограничения | 🔜 |
| `/passphrase` | генерация парольной фразы (Diceware) | 🔜 |
| `/check` | оценка стойкости и проверка по базе утечек | 🔜 |
| `/audit` | аудит выгрузки из менеджера паролей | 🔜 |
| `/services` | учёт сервисов, даты смены паролей, наличие 2FA | 🔜 |
| `/breaches` | совпадения сервисов с каталогом утечек | 🔜 |
| `/report` | сводка по парольной гигиене | 🔜 |

Справка формируется автоматически из реестра команд: добавление новой команды означает добавление одного класса, правки в `/help` не требуются.

## Сборка и запуск

Требуется JDK 21 и Maven 3.9+.

```bash
mvn clean package
java -jar target/passwordcheck.jar
```

## Тесты

```bash
mvn test
```

## Конфигурация

Задаётся переменными окружения:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `TELEGRAM_BOT_USERNAME` | имя бота |

Токен в репозиторий не коммитится. Образец конфигурации — в `.env.example`.

## Структура проекта

```
src/main/java/ru/urfu/passwordcheck/
    bot/          приём сообщений, разбор команд, отправка ответов
    command/      реестр команд и их реализации
    strength/     оценка стойкости: матчеры и поиск разбиения
    breach/       клиент HIBP, k-anonymity
    generator/    генерация паролей и парольных фраз
    audit/        разбор выгрузок из менеджеров паролей
    storage/      учёт сервисов пользователя (без секретов)
src/main/resources/
    wordlist/     словари для генерации и оценки стойкости
src/test/java/    функциональные и модульные тесты
```

Логика команд отделена от транспорта: команда принимает разобранный запрос и возвращает ответ, ничего не зная о Telegram. Благодаря этому команды тестируются без сети и без реального бота.

## Разработка

**Ветки.** Разработка ведётся в отдельных ветках, `main` защищена. Именование: `feature/<краткое-описание>`, `fix/<краткое-описание>`.

**Коммиты.** Атомарные: один коммит — одна задача. Рефакторинг, исправление ошибок и новая функциональность не смешиваются. Перед коммитом код должен компилироваться и проходить тесты.

**Слияние.** Только через Pull Request с ревью второго участника. Перед созданием PR ветка синхронизируется с `main`.

## Дорожная карта

1. Каркас бота, команды `/author`, `/about`, `/help`, сборка через Maven.
2. Генератор паролей и парольных фраз: `SecureRandom`, словарь Diceware, устранение modulo bias, генерация под ограничения алфавита и длины.
3. Проверка по базе утечек: SHA-1, k-anonymity, `Add-Padding`, кеш префиксов, обработка недоступности сервиса.
4. Базовая оценка стойкости: словарь частотных паролей, перевод в время взлома по моделям атакующего.
5. Матчеры: клавиатурные последовательности QWERTY и ЙЦУКЕН, даты, повторы, l33t, транслит.
6. Поиск разбиения минимальной стоимости, сборка итоговой оценки.
7. Аудит выгрузок: парсеры форматов, батчинг запросов, поиск переиспользования, приоритизированный отчёт.
8. Профиль сервисов: аккаунты, даты смены паролей, наличие 2FA, рекомендации.
9. Каталог утечек: загрузка, сопоставление с профилем, фоновое обновление, уведомления.
10. Гигиена секретов как набор тестов: отсутствие утечек в логи, обнуление буферов, удаление сообщений, ограничение частоты запросов.
